# CHRONOS-MEM DEVELOPMENT, GIT WORKFLOW & SCALE PLAN

### STRICT GIT PROTOCOL
- NEVER push code directly to the 'main' branch. 
- All development must occur on descriptive, isolated feature branches (e.g., feature/01-postgres-core).
- Every branch must be merged into 'main' via a GitHub Pull Request (PR) after a careful peer review of the AI-generated code.

===========================================================================
PHASE 1: THE LOCAL CORE MVP (WEEKS 1–4)
===========================================================================

### MILESTONE 1: HYBRID POSTGRES ENGINE & ENVIRONMENT (WEEK 1)
- Goal: Provision local Postgres with pgvector and compile core schemas for chronos-mem.
- Tasks:
  1. Write 'db/docker-compose.yml' targeting PostgreSQL 16 + pgvector.
  2. Write 'db/migrations/001_init_chronos_schema.sql' defining the 5 pillars (memories, plans, actions, outcomes, interventions) using JSONB for flexible data, strict foreign keys for causality, and an analytical view for tool brittleness.
- Branch: feature/01-postgres-core

### MILESTONE 2: ASYNC PYTHON SDK CORE (WEEK 2)
- Goal: Build the developer-facing client application wrapper.
- Tasks:
  1. Write 'sdk/python/chronos_mem/client.py' to manage safe async connection pools using psycopg3.
  2. Write 'sdk/python/chronos_mem/tracking.py' exporting .create_plan(), .log_action(), .log_outcome(), and .log_intervention() returning clean Pydantic v2 models.
- Branch: feature/02-python-sdk

### MILESTONE 3: CAUSAL TRACING & INTERVENTION ENGINE (WEEK 3)
- Goal: Build the debugging query layer to explain timeline failures and pull historical fixes.
- Tasks:
  1. Write a PostgreSQL Recursive Common Table Expression (CTE) query to trace multi-agent graph failures backwards through ancestry IDs.
  2. Expose this inside the SDK via 'db.query_causality(plan_id)' and 'db.get_best_intervention(error_type)' ensuring a sub-5ms return time.
- Branch: feature/03-causal-queries

### MILESTONE 4: DEBUG GRAPH UI & BENCHMARKS (WEEK 4)
- Goal: Build the visual timeline flowchart tracer and assert latency metrics.
- Tasks:
  1. Create a 1-page Streamlit/FastAPI debugging dashboard ('dashboard/app.py') that visually parses execution trees and highlights failed plan nodes in red.
  2. Write 'tests/benchmark_perf.py' simulating 1,000 parallel agent calls to verify under 5ms write/read speeds.
- Branch: feature/04-dashboard-benchmarks
